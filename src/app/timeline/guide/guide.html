Oppdater tidslinjen sammen med Claude.

Tidslinjeverktøyet er bygget for å vedlikeholdes med Claude Code: du peker på dokumentasjonen du har på maskinen — referater, feature-specs, veikart — og Claude oversetter den til oppdaterte rader, datoer og avhengigheter. Mappen inneholder en CLAUDE.md som lærer Claude datamodellen automatisk når en økt startes her.

Slik gjør du det

Eksporter arbeidsflaten din

Åpne tidslinjeverktøyet — lokalt (gantt.html) eller via SkyTracker-adressen — og trykk Eksporter. Legg skytale-telenor-plan.json i denne mappen (~/Skytale/ClaudeReports/telenor-timeline/). Dette er nødvendig fordi endringene dine lagres i nettleseren — Claude kan ikke lese dem uten eksporten.

Start Claude Code i mappen

Åpne terminalen og kjør cd ~/Skytale/ClaudeReports/telenor-timeline && claude — eller start i ~/Skytale og be Claude lese ClaudeReports/telenor-timeline/CLAUDE.md først.

Pek på dokumentasjonen og si hva du vil

Claude leser dokumentene, oppdaterer JSON-filen etter datamodellen, og sier fra når den er klar. Se eksempler under.

Importer resultatet

Tilbake i gantt.html: trykk Importer og velg den oppdaterte JSON-filen. Verktøyet rydder selv opp i avhengigheter og delmål. Se over resultatet — og eksporter gjerne på nytt som sikkerhetskopi.

Eksempler på ting du kan be om

# Fra møtereferat til plan:
Les referatet i ~/Skytale/ClaudeReports/feature-specs/... og oppdater
tidslinje-JSON-en: F-24 vår del er utsatt to uker, legg inn beslutningen
om vaktplan som ny rad under Sikkerhet med start i oktober.

# Konsistenssjekk mot dokumentasjon:
Sammenlign tidslinjen med delivery-planen i ClaudeReports/delivery-plan/
og list opp avvikene før du endrer noe.

# Baseline-endring (det Nullstill går tilbake til):
Oppdater SEED i gantt.html og den redaksjonelle index.html slik at
ARR-målet flyttes til januar — begge skal fortelle samme historie.
SkyTracker-radene er speil. Rader merket ST kommer fra SkyTracker-synken og overskrives ved neste trykk på «Synk SkyTracker». Endringer i teknisk plan gjør du i SkyTracker, og synker på nytt: åpnet via SkyTracker-adressen henter knappen live data direkte; åpnet lokalt kjører du sync-skytracker.command først. Be gjerne Claude kjøre synken for deg: «kjør SkyTracker-synken og fortell meg hva som er endret».

Gjelder dette også SkyTracker-versjonen?

Ja. Verktøyet finnes i to utgaver som oppfører seg likt: HTML-filen i denne mappen, og siden /timeline i SkyTracker (bak Microsoft-innloggingen). Claude-arbeidsflyten er identisk — Eksporter → Claude redigerer → Importer — fordi planen din uansett bor i din egen nettleser.

Jobber du fra en maskin som ikke har denne mappen (f.eks. et teammedlem som bruker SkyTracker-versjonen): eksporten er selvforklarende JSON. Be Claude lese den eksporterte filen direkte og beskriv endringene du vil ha — feltene (lanes, tasks med start/end i måneder siden 1. august 2026, deps, subtasks) står forklart i CLAUDE.md, som også kan sendes med som kontekst.

Hva Claude vet fra før

  • Tidsmodellen — måneder siden 1. august 2026, akse til desember 2027.
  • Datamodellen — lanes, tasks, delmål, avhengigheter (finish-to-start), T1/T2-merking.
  • Grensene — aldri håndredigere skytracker-data.js, aldri røre ST-rader manuelt, holde gantt.html og eksport-scriptet enige om tidsmodellen.

Alt dette står i CLAUDE.md i denne mappen — den er kontrakten mellom verktøyet og Claude.
